## 5. In scope (exact)

Backend:
- `GET /api/v1/{locale}/shell` (locale pl|en else 404): JSON { locale, theme, sidebar, navGroups:[{label, items:[{label, icon, route, href, badge?}]}], currentSection (derived from a `route` query param mirroring Navigation::currentSection), crumb, workspace:{name, meta, mark}, user:{name, email} } — values identical to PanelContext/Navigation/Workspace/PanelIdentity (default identity maciej@aureashop.pl / Maciej Kowalczyk; name derivation from e-mail local part exactly as PanelIdentity::name).
- `POST /{locale}/login` (form `_username`, `_password`): valid e-mail → store in session, 302 to `/{locale}/dashboard`; empty → 200 with message "Podaj adres e-mail."; malformed (not `filter_var(FILTER_VALIDATE_EMAIL)`-valid — use a strict RFC-ish validator matching PHP's for the oracle inputs) → 200 with "To nie wygląda na poprawny adres e-mail.". The 200 response is the SPA document (see "SPA document") carrying `data-login-error` and `data-last-username` attributes on `<html>` so the SPA renders the login page with the callout and the retained value.
- `POST /{locale}/logout` → clear identity, 302 to `/{locale}/login`.
- `POST /preferences/theme` JSON {theme} → 200 {theme} (dark|light, fallback light); `POST /preferences/sidebar` JSON {state} → 200 {state} (collapsed|expanded, fallback expanded). Also accept form-encoded like PreferencesController::readValue.
- SPA document: for every known panel/public route pattern (the 27 routes in inventory/routes.json minus /_storybook, /collect, /preferences/*, /import/upload) respond 200 with `index.html` from the built SPA, injecting `lang="{locale}"`, `data-theme`, and `data-sidebar` from the session before first paint (no flash). Unknown locale prefix (`/de/...`) and paths outside the route table → 404 with a minimal HTML document (status is what is compared; DEV-12). `/` → 302 to `/pl` if that is what the oracle landing step 3 recorded (check journeys/landing/steps/3/http.jsonl and step.json; reproduce the recorded status/redirect exactly).
- Session: Spring Session JDBC, cookie `SESSION`, HttpOnly, SameSite=Lax, Secure=auto behind the proxy (`server.forward-headers-strategy=framework`).
- Actuator `/actuator/health` (not exposed via the edge? keep it internal or under /api/v1/health — your call, record it).
